# Устройство rts_bot

## Общая схема

```
Telegram ──(опрос, поток 1)──> telegrambot.py ──> variables.py (словарь о сообщении)
                                    │                    │
                                    │                    ├─> db.py (лимиты человека, реакции, подсчёты, запись)
                                    │                    └─> reaction.py / checkmessage.py (решения и ответы)
                                    └─(расписание, поток 2)──> scheduletask.py (стикеры по будням в 9:00)
```

`bot.py` вызывает `telegrambot.runbot()`, который запускает два потока: опрос Telegram и расписание. Если один из потоков
падает, второй заканчивает работу (общий флаг `crash`).

## Как обрабатывается сообщение

1. `telegrambot.py` принимает сообщение (типы: аудио, фото, голос, видео, документ, текст, локация, контакт, стикер, гифка, кружок)
   или правку сообщения.
2. `variables.variables` собирает всё о сообщении в один словарь `variablesdict`: чат, автор, текст, время и границы
   «месяц, неделя, сутки, час, 10 минут назад».
3. `db.clearbase` удаляет записи старше 30 дней.
4. `variables.variableslimits` читает лимиты автора: сначала его личную строку, а если её нет — общую (`allmembers`).
5. `reaction.newmessage` проверяет лимит типа сообщения: `-1` — удалить и сообщить, число — сравнить с количеством за сутки,
   за одно сообщение до предела предупредить. Для VIP (`vip = 100`) проверка пропускается.
6. Если сообщение не нарушило лимит, `db.checkuserreaction` ищет реакции для типа сообщения и вызывает
   `checkmessage.regextext`: она ищет регулярное выражение в тексте и отвечает текстом или стикером. Ответ не чаще раза в час
   на одну реакцию; метка `21` считает «текстовые нарушения» за сутки.
7. `db.basewrite` записывает сообщение в таблицу чата.

Команды: `/version` и `/statistics` (отвечают не чаще раза в час). Добавление бота в чат вызывает приветствие чата,
новый участник — приветствие участника.

## База данных (SQLite, файл `rtsbot.db`)

| Таблица | Что хранит |
|---|---|
| `bot_settings` | токен, номер и имя бота (одна строка) |
| `<chat_id>` | все сообщения чата за последние 30 дней: автор, тип, текст, подпись, метка нарушения, время |
| `<chat_id>_limits` | лимиты: строка `allmembers` для всех и личные строки по участникам; столбцы по типам сообщений и `violation`, `vip` |
| `<chat_id>_reaction` | реакции: тип сообщения, тип ответа, регулярное выражение, ответ, метка нарушения |

Для каждого чата создаётся свой набор таблиц, имя берётся из номера чата.

## Известные особенности (оставлены как есть)

- Строка лимитов человека **целиком** заменяет общую: незаполненное значение `0` означает «разрешено». В BMFT лимиты наследуются по полям.
- В `db.py` описаны ветки для `mysql` и `postgresql`, но они пустые (`pass`): работает только `sqlite`.
- Состояние хранится в одном большом словаре, который передаётся между функциями; глобальные переменные `bot` и `crash`
  меняются из нескольких потоков без блокировок.
- Настройки чатов правятся прямо в базе: интерфейса нет.
